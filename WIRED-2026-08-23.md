# Babble, fever, and hand — wired into app/index.html (2026-08-23)

`app/index.html` now runs pages 30–34, 35–46, and 51 for real, the same
way 28–29 (crate), 47–48 (NO), 49 (hole), and 50 (collapse) already were.
Nothing in any LOCKED file was edited — see exactly what changed below.

## What's now live in the app

| Pages | Section | How it's mounted |
|---|---|---|
| 30–34 | babble (MA→DA→GA→UH) | closure-isolated, verbatim body from `babble-30-34-LOCKED.html`, at `#seq-babble` |
| 35–46 | fever/effects | closure-isolated, verbatim body from `fever-35-46-LOCKED.html`, at `#seq-fever` |

`SEQ.at` was extended to map all of 30–51 to these three modules, the
same map that already carried 28–29/47–50.

## One real difference from the crate/NO/hole/collapse pattern

Those four are non-interactive scenes — they run off a clock, and their
own `addEventListener` calls only ever get replayed once, at the moment
they're mounted (an initial `click` replay firing once, nothing live
after that). That's fine for a clock-driven scene, but babble and fever
are actual minigames — the reader has to hold/release to build a
syllable, or find/hold a matching pair — so a one-time replay would
leave them frozen the instant they came on screen.

So for babble and fever specifically, the shim also attaches real,
live `window` listeners (touchstart/touchend/mousedown/mouseup/etc.)
gated on whether that module is currently the one showing. That's the
only structural change from the existing pattern; the locked bodies
themselves are spliced in byte-for-byte otherwise.

## The hand (51) — why it's an iframe, not a splice

The crate/no/hole/collapse/babble/fever pattern works because those
files all use exactly `document.getElementById('c')` for their canvas
and `'hud'` for their HUD — the shim only needs to redirect those two
ids. `hand-51-LOCKED.html` is a different shape: its own `<body>`, an
image element, a Reset button, several distinct ids, and a
`navigator.vibrate` loop. Splicing it into the same two-id shim would
break it. Mounting it as `./locked-hand-51.html` inside a same-document
iframe keeps the file completely untouched and just as locked as
before, while still making it show up for real at page 51.
(`navigator.vibrate` inside a same-document iframe should work; if the
device blocks it there, that shows as a harmless console warning, not
a functional break — same caveat that was already noted for it earlier
in the project.)

## What this does NOT do

- It doesn't gate page-advancement on completing babble/fever's game —
  swiping through pages 30–34/35–46 still works even without touching
  the mark/pair, exactly like swiping through the crate doesn't require
  watching the whole scene. That's consistent with how 28–29/47–50
  already behave, not a new gap introduced here.
- It doesn't add sound or haptics — still the agreed next phase.
- `app/index.html` is otherwise untouched: pages 1–27 and the whole
  title/gate flow are byte-identical to what was in this repo already.
